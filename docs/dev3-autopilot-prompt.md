## Hard rules (break any of these and the run fails)

1. **Branch:** `git checkout dev && git checkout -b dev3/backend-voice`. Commit after each task with a short
   present-tense message like `voice: fix double death line`. **Do not push, merge, or rebase. Do not touch `main`.**
2. **Ownership:** only edit `backend/`, `frontend/src/audio/`, `frontend/src/net/`, the deploy config files listed below,
   and `docs/dev3-*.md`. You may add **small, clearly marked hook-ins** (under 15 lines each, with a comment like
   `// Dev 3 hook: ...`) to `frontend/src/game/scenes/GameOverScene.ts`, `MenuScene.ts` and `frontend/src/main.ts`.
   Put all real logic in Dev 3 files. This keeps merge conflicts with Dev 1 and Dev 2 small.
3. **Do not change `frontend/src/shared/`** (the integration contract). If you think you need to, write it in the
   report under "Contract change requests" and work around it.
4. **The game loop never waits on the network or an AI call.** The game must build and run with the backend off and
   with `VITE_BACKEND_WS` unset.
5. **Secrets:** never print, log, or commit values from `backend/.env`. You may check whether a key is set.
6. **ElevenLabs/Gemini credits cost money:** use the hash cache, never render the same thing twice, and cap live
   roast smoke tests at 10 calls per run.
7. If a step needs a human (account sign-up, domain, dashboard env vars, listening to audio), **don't stop**.
   Log it under "Human TODO" in the report and move on.
8. Keep code in the style of the files around it: short header comment naming the owner and ticket, small functions,
   no new frameworks. Allowed new deps: `pytest` (backend dev only). No new frontend deps.

## Task 2: Voice director fixes (Ticket #15, M3, P0)

**Objective:** a full run plays 3 to 6 voice lines, never overlapping, and never two lines on one death.

Steps in `frontend/src/audio/VoiceDirector.ts` and `frontend/src/net/Socket.ts`:
- **Double death fix:**
  - On `death`, if a live roast is expected (`Socket` exposes `willRequestRoast(): boolean`, true only when connected
    and this is a roast death), hold the cached death line for 1.6 s.
  - If `roast` arrives first, cancel the cached line and play the roast.
  - On `roast_fallback` or timeout, play the cached line.
  - If no roast is expected, play the cached line immediately.
- **Socket fixes:**
  - Register the EventBus listener once (in the constructor or behind a guard), not per reconnect.
  - Clear the reconnect timer properly.
  - Never throw on malformed JSON.
- **Ducking API:**
  - `VoiceDirector.registerMusic(howl: Howl)`. While a voice clip plays, fade that music to 60% volume, then restore it.
  - No-op if no music is registered. Remove the `Howler.volume(1)` global reset.
- Put the timings (`GLOBAL_COOLDOWN_MS`, `EVENT_COOLDOWN_MS`, `ROAST_WAIT_MS`) as named constants at the top.
- Add a dev-only debug hook: `window.__voice = voice` in `main.ts`, inside `if (import.meta.env.DEV)`.

**Validation output:**
- `npm run build` passes.
- Add `frontend/src/audio/voiceDirector.selftest.ts`, a pure-logic test of the cooldown and priority decision function.
  Pull that decision out of `VoiceDirector` into a pure function `shouldSpeak(state, event, now)` so it can be tested
  without Howler. Run it with `npx tsx` if available, or compile with `npx tsc` to a temp dir and run with node.
- The test asserts all of these:
  - No second line within 4 s.
  - The same event is blocked for 10 s.
  - Death always gets through.
  - Death interrupts lower priority.
  - The last 2 line ids don't repeat.
- Paste the test output.

## Task 4: Dynamic death roast end to end (Ticket #22, M3)

**Objective:** dying twice reliably gets a stat-specific roast in under 2 s. Without the network, a cached line plays

Steps:

  - Validate the WS `death` payload with a pydantic `RunStats` model.
  - Give Gemini a 1.5 s timeout and ElevenLabs a separate cap so the total stays under 2.5 s.
  - Log `roast ok in X ms` / `roast fallback: reason` with no secrets.
  - Tune `build_prompt()` to use more stats (`durationS`, `nearMisses`, the `best - altitude` gap) and to vary its
    angle. Keep it to 15 words max, family friendly, one line, no quotes or emojis.

- **Smoke script** `backend/scripts/roast_smoke.py`:

    iterating, and do one full run at the end.

  - Success returns `{text, audio_b64}`.
  - A Gemini exception returns None.

  - A WS test via `TestClient.websocket_connect` checks that `death` yields `roast` or `roast_fallback`, and `score`
